# Physical bench procedure — not yet executed

No physical sample capture, flash/upload, oscilloscope observation, supply measurement, or RF transmission was performed in this environment. Execute and record these steps on the actual ESP32-WROOM-32 assembly before treating it as a sensing node.

1. **Front end and pin confirmation.** Record the ESP32 board revision, actual ADC1 GPIO, MCP6002 circuit/gain and supply rails, piezo bias and protection, and measured anti-alias response. The piezo can produce bipolar voltage spikes. Verify its signal is biased, attenuated and clamped before reaching ADC1; never connect an unprotected disc directly to the ADC. Avoid exceeding the board/chip input limits or driving a powered-down ESP32. A digital bandpass cannot remove analog aliasing that has already occurred. Confirm analog attenuation above 4 kHz at the sensor/conditioner output. Supply/ground/decoupling and the antenna must be correct before RF tests.
2. **Safe initial flash.** Build with the pinned versions, flash the default synthetic configuration and leave RF disabled. Send `c`; retain the diagnostics and payload hex. Decode it on the host and confirm 15x13 shape, scale, and synthetic code labels. Check heap minimum/largest-block diagnostics; no large buffer should be silently assumed to fit. The host's DSP runtime is not an ESP32 runtime.
3. **Physical acquisition.** Configure the real ADC1 GPIO and node/date/battery codes, set `BENCH_MODE=false` and keep RF disabled. Apply a DC level within the verified input range, capture, then apply an asymmetric slow ramp/step to verify ADC channel tags and adjacent-sample ordering for `ADC_SWAP_ADJACENT`. Confirm output has exactly 80,000 retained samples and no overflow/timeout. Record elapsed acquisition time and compare repeated captures with an external calibrated clock/signal source. The firmware's 2% duration check is only a coarse fault detector. Investigate any x2 or x0.5 rate or pair-order artifact instead of changing preprocessing to hide it.
4. **Known signals and amplitude.** Inject calibrated 100 Hz, 500 Hz, 1 kHz and 2.5 kHz tones, then out-of-band signals, without violating the analog input range. Sweep amplitude and ADC bias across the front end's linear range. Record raw min/max, rail counts, retained duration, DSP time, scale, quantized matrix and application length. Compare repeatability and the bandpass response with the function generator/oscilloscope and the reference pipeline for the actual captured input. Voltage-to-code gain/nonlinearity must be characterized separately: the firmware deliberately uses linear raw counts, not a claim of calibrated acoustic amplitude. Confirm a quiet/constant input is encoded, not gated away.
5. **Numerical comparison on target.** The native shared-code tests in `host/verify.py` establish host agreement only. Execute that same fixed PCM input on the ESP32 (temporarily fill the existing PCM chunks with the saved vector, as the synthetic path does), capture the scale/payload, and compare it byte-for-byte with the host encoder/reference result. Start with the checked-in synthetic 500 Hz formula, then edge impulses and noise. Use waveform tolerance 1e-10 and MFCC tolerance 1e-7 only as initial algorithmic targets; actual on-target libm behavior must be measured. Any quantized/scale/payload mismatch must be retained and reported, especially if close to a rounding boundary. Do not claim bit identity for physical ADC recordings merely because synthetic/native tests pass.
6. **Radio-only test.** Supply explicit module/antenna-compatible permitted radio settings on sender and receiver, with matching SF/BW/CR/sync word/preamble, explicit header mode and CRC. Verify the actual permitted band and TX power independently; no region was assumed in code. To send the synthetic example, deliberately enable both RF and synthetic RF and label its header as synthetic. Confirm the receiver obtains the identical application bytes, decodes all 195 coefficients and scale, and reports any PHY CRC errors. Sender `TX_DONE` is not a receiver acknowledgment.
7. **Limits and real capture.** Verify payload rejection with the alternating ±127 host case (5,947 required application bytes). It must never be silently truncated, raw-fallback encoded, fragmented or sent as a different protocol. Then transmit a real valid capture and confirm node ID/date/battery code meaning with the caller; date (unsigned 0..31) and battery (unsigned 0..7) semantics remain undefined. Confirm node ID is unsigned 0..255 and both receiver and sender use the current 5+3 packing rather than the earlier 4+4 layout. Record ADC duration/overrun/clipping, peak/remaining heap, DSP and encoder latency, payload length, LoRa configuration and actual received bytes. Account for radio/PHY headers separately from application bytes. An airtime/duty-cycle assessment requires those actual settings and local rules.

Report observed results separately from these instructions. Leave failures visible and retain their raw diagnostic output. Deep sleep and measurement scheduling are future work.
